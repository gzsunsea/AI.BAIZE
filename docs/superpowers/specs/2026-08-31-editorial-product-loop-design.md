# AI.BAIZE 三阶段编辑产品闭环设计

## 目标

在已有的证据优先、今日先看、热点事件、阅读工作台和报告能力上，完成三阶段产品闭环：

1. 把精选首屏稳定成可快速判断的每日刊物入口；
2. 把日报积累为周报/月报中的趋势主线，并把单次热点沉淀为可追踪事件；
3. 让用户从阅读、核验、收藏、导出到反馈形成闭环，同时保留 RSS/API 这种低成本订阅方式。

## 设计决定

- 不增加付费 API、付费数据源或邮件基础设施；订阅优先使用现有 RSS，报告使用浏览器端 Markdown 导出。
- 不改变 `data/db.json` 的运行时数据结构；趋势和生命周期均从现有条目、日报快照和事件簇实时计算。
- 事实、编辑整理、创作建议、用户反馈分开存储和展示。
- 事件只在已有明确聚合关系时合并；生命周期显示状态和证据，不制造未经证实的因果判断。
- 反馈入口只收集内容质量和使用价值，不收集个人画像；每条反馈带上可选的内容 ID 和页面上下文，便于后台处理。

## 用户流程

```text
今日先看
  -> 进入事件 / 阅读工作台
  -> 核对事实、证据边界和关联来源
  -> 收藏、标记处理、导出或打开原文
  -> 对内容提交有价值 / 重复 / 需核验反馈
  -> 日报快照累计为周报主线与主题趋势
```

## 交付范围

### 第一阶段：每日刊物入口

- 今日先看显示本期更新时间、信号数量和编辑摘要；候选不足时保持真实数量。
- 每条信号继续显示证据层级、独立信源、最新时间和可复用价值。
- 事件页补充首次出现、最近更新、当前生命周期状态和下一步核验提示。

### 第二阶段：趋势与生命周期

- 报告 API 增加 `trendLines`、`editorialSummary` 和 `watchItems`。
- 趋势线按规范化主题/类别聚合，记录出现次数、涉及事件数、最新时间和证据强度。
- 事件生命周期提供 `emerging`、`confirmed`、`developing`、`stale` 状态，以及首见/最近更新时间。
- 报告页展示“本期主线”和“继续观察”，支持跳转到对应内容。

### 第三阶段：订阅、导出与反馈

- 报告页提供 RSS 订阅入口和当前报告 Markdown 导出。
- 阅读工作台提供内容级反馈动作，包含“有价值”“重复/噪音”“事实需核对”。
- 反馈写入既有 `/api/feedback`，增加 `kind`、`itemId`、`context` 字段并继续通过后台管理处理。
- 反馈失败不阻塞阅读、原文、收藏、处理和导出动作。

## 错误处理与降级

- 趋势计算没有足够数据时返回空数组和明确的“样本不足”摘要，不补造趋势。
- 事件无法计算生命周期时保留现有事件页和时间线，省略生命周期卡片。
- RSS 或导出入口不可用时，报告阅读和原文动作保持可用。
- 反馈接口失败只显示可重试提示，不影响阅读工作台。

## 验收标准

- 今日先看不超过 5 条、不重复事件、不包含 `reference` 内容，并显示本期摘要。
- 周报/月报返回趋势主线、证据强度和继续观察项；无数据时不伪造主线。
- 事件页能展示首见、最近更新和生命周期状态，且时间线仍只包含公开有效内容。
- 报告可导出 Markdown，RSS 入口可访问，内容级反馈包含内容上下文并可在后台看到。
- `npm test`、`npm run typecheck`、`npm run build` 全部通过；人工检查桌面/移动端无横向溢出。
