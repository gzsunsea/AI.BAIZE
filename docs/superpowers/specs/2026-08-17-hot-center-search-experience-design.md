# AI.BAIZE 热点中心与搜索体验设计

日期：2026-08-17
状态：已获用户确认，待拆分实施计划

## 1. 背景与目标

对标站近期把“信息流”升级为“事件中心”：热点榜负责回答“现在什么正在形成共识”，事件页负责回答“这件事发生了什么、进展到哪一步、有哪些来源”。本站已经具备来源分层、事件聚类、关联报道和阅读工作台，但热点仍停留在精选页的局部组件，故事打开后也没有可分享的稳定地址，搜索与浏览器返回无法恢复上下文。

本轮目标：

1. 新增可独立访问、可分享的热点中心 `/hot`。
2. 新增事件详情 `/story/:id`，提供最新摘要、来源和时间线。
3. 让搜索模式、筛选状态和打开位置进入 URL，并在返回时恢复列表上下文。
4. 继续使用本站已有内容和来源质量策略，不引入付费数据源，不镜像对标站内容。

## 2. 用户场景

### 2.1 快速判断热点

用户进入“热点”页，希望在几十秒内看到近 72 小时内正在形成共识的事件，知道每个事件的来源数、最新时间、热度和状态，并能进入详情核查来源。

### 2.2 追踪一个事件

用户从热点卡片或信息流进入事件详情，希望看到一段事实摘要、最新进展、来源列表和按时间排序的关联报道；点击浏览器返回后，仍回到原来的热点/信息流位置。

### 2.3 搜索与回看

用户搜索关键词，能够明确选择“直接匹配”或“全文相关”；刷新或复制 URL 后结果一致；从结果打开多条内容再返回，不丢失查询、筛选、排序和滚动位置。

## 3. 方案选择

采用“原生热点中心 + 原生事件详情 + URL 状态路由”。

不采用仅抽屉方案：抽屉适合快速预览，但无法提供稳定深链接和浏览器历史语义。
不采用外部跳转方案：会让本站体验不闭环，并产生外部服务依赖。

## 4. 信息架构与交互

### 4.1 导航

- 在主导航加入“热点榜”，入口指向 `/hot`。
- 精选页保留“当前热点”预览，点击“查看完整热点榜”进入 `/hot`。
- 热点榜详情进入 `/story/:id`。
- 原有阅读工作台仍可从普通信息流打开；本轮不删除现有工作台能力。

### 4.2 热点中心 `/hot`

页面结构：

1. 页面标题、更新时间和规则说明。
2. 排名列表（最多 10 个事件，首期可以沿用现有前 5 个聚类并扩展接口容量）。
3. 每张卡片展示：排名、事件标题、热度分、状态、独立来源数、来源名称、最新更新时间、代表性摘要。
4. 提供“全部来源”展开入口，进入事件详情。
5. 空态说明“近 72 小时暂无达到多源确认阈值的热点”，不伪造内容；接口失败时保留可重试状态。

热度分首期采用可解释的本站指标：

```text
heat = sourceQualityScore + sourceCountBonus + freshnessBonus + selectedScoreBonus
```

实际字段和权重由后端常量统一定义，并在接口 `rules` 字段和前端“规则说明”中展示。首期不声称拥有外部讨论量，也不生成历史热度曲线。

状态按热度和发布时间计算：

- `new`：最近 6 小时首次出现；
- `rising`：来源数量或热度较当前窗口前一时段增加；
- `active`：仍在 72 小时窗口内且保持多源确认。

如果现有数据不足以判断变化量，退化为 `active`，并在接口中标记 `trendAvailable: false`。

### 4.3 事件详情 `/story/:id`

页面结构：

1. 返回入口：根据来源页显示“返回热点榜”或“返回信息流”。
2. 事件状态、来源数量、最新更新时间。
3. “事件全貌”摘要：由代表性内容的 editorial brief、摘要和推荐理由拼接，明确标注为本站编辑摘要。
4. “最新进展”：取关联报道中发布时间最新的 1–3 条。
5. “事件时间线”：按发布时间倒序展示所有关联报道，标注来源、时间、频道和原文链接；官方/一手信源使用现有 channel/source tier 标记。
6. 相关操作：收藏、已读、稍后读、问白泽沿用现有能力。

事件 ID 使用现有 `cluster.id || representative.eventId || representative.id` 规则。详情接口找不到事件时返回 404，前端显示可返回的明确空态。

### 4.4 搜索

增加 `searchMode`：

- `direct`（默认）：仅匹配标题、摘要、来源名称和标签，按发布时间严格倒序；
- `full`：在 direct 字段之外匹配正文/编辑摘要等可公开全文字段，仍按相关度优先、发布时间作平局排序。

搜索状态写入 URL：`q`、`search`、`tag`、`channel`、`category`、`sort`、`page`。空值不写入 URL，保持链接简洁。

### 4.5 返回与历史状态

- 列表视图进入详情时 `pushState`，详情返回使用 `history.back()`；没有历史记录时退回 `/hot` 或当前列表。
- 列表页在离开前保存 `scrollY` 和关键筛选状态；`popstate` 后先恢复数据状态，再在下一帧恢复滚动。
- 直接打开 `/story/:id` 时不依赖前置列表，详情接口自行加载关联数据。
- 中键、⌘/Ctrl 点击和右键新开页保持原生行为，不拦截为单页切换。

## 5. API 与数据契约

### 5.1 热点列表

`GET /api/public/hot`

```json
{
  "generatedAt": "2026-08-17T00:00:00.000Z",
  "windowHours": 72,
  "rules": { "version": 1, "trendAvailable": false },
  "items": [
    {
      "id": "event-id",
      "rank": 1,
      "title": "事件标题",
      "heat": 86,
      "status": "active",
      "sourceCount": 3,
      "sources": ["来源 A", "来源 B"],
      "publishedAt": "2026-08-16T23:00:00.000Z",
      "latestAt": "2026-08-17T00:00:00.000Z",
      "representative": {},
      "relatedItems": []
    }
  ]
}
```

保留 `/api/public/hot-topics` 兼容现有精选页，或在同一提交中将其改为调用统一构建函数，避免两套热点排序逻辑。

### 5.2 事件详情

`GET /api/public/stories/:id`

返回 `event`、`summary`、`latestUpdates`、`timeline`、`sources`、`rules`。`timeline` 中每项复用公开 `Item` 装饰字段，不返回管理字段、抓取凭证或敏感运行状态。

### 5.3 信息流搜索

在现有信息流接口增加 `search` 或 `searchMode` 参数，默认 `direct`，响应中回显：

```json
{ "search": { "query": "...", "mode": "direct", "sort": "published_desc" } }
```

旧参数继续兼容，避免影响日报、主题和管理端调用。

## 6. 前端结构

- 新增 `HotPage` 和 `StoryPage` 组件，复用现有卡片、来源徽标、操作按钮和阅读工作台样式。
- 在 `App` 中引入轻量路由解析：根据 `location.pathname` 和 `URLSearchParams` 派生页面与筛选状态。
- 使用统一 `navigate()` 封装 `pushState`、`replaceState` 和 `popstate`。
- `FeedExperience` 增加搜索模式控件和当前 URL 状态同步，但不改变现有信息流卡片视觉系统。
- 详情页支持加载中、404、接口错误和无关联报道四种状态。
- 移动端保持单列；热点卡片和时间线不得产生横向溢出；操作按钮遵循现有触控尺寸。

## 7. 无障碍与性能

- 排名列表使用语义化列表；状态和热度不可只依赖颜色表达。
- 时间线使用有序列表和 `<time>`，来源链接有明确可读名称。
- 搜索模式使用带标签的 radio/tab 语义，并支持键盘切换。
- 图片和媒体继续懒加载；热点列表首屏只加载代表性媒体，详情按需加载全部关联内容。
- 不为每次滚动写入 URL；仅在离开列表时保存内存/会话状态，避免历史记录膨胀。

## 8. 验证计划

后端：

- 热点列表排序、热度、状态和 72 小时窗口单元测试。
- 事件详情 200/404、关联报道排序和敏感字段过滤测试。
- direct/full 搜索结果、排序和旧参数兼容测试。

前端：

- URL 解析与生成测试。
- `/hot`、`/story/:id` 加载/错误/空态测试。
- 详情返回后恢复筛选和滚动位置的浏览器测试。
- 移动端 390px 宽度下无横向溢出检查。

验收标准：

1. 用户可以从精选页进入热点中心，再进入可复制的事件详情链接。
2. 事件详情至少显示 2 条（若数据存在）按时间排序的关联报道和来源信息。
3. 搜索模式、筛选、分页和排序刷新后保持一致。
4. 浏览器返回恢复原页面状态和大致滚动位置。
5. 无付费 API、无外部热点页依赖、无生产 `data/db.json` 覆盖。

## 9. 本轮不做

- 模型评测榜、价格数据管线和 benchmark 详情。
- 外部讨论量接入和历史热度曲线持久化。
- 对标站内容镜像、抓取或复制。
- 重做现有阅读工作台、日报和移动端视觉系统。
