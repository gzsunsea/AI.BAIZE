# AI.BAIZE 只读 MCP 接入设计

日期：2026-09-28
状态：设计草案，待用户复核
范围：本地只读 MCP 接口；不包含生产启用或部署

## 背景与目标

AIHOT 近期把 Agent 接入扩展到 MCP，并让 Agent 可读取精选、热点、事件时间线和日报。它此前已提供 REST、RSS 与 Skill。AI.BAIZE 当前也已有 REST、RSS、Skill 与事件聚合能力，因此本项目应吸收的是“让 MCP 客户端直接调用精选内容和事件上下文”的接入方式，而非复制 AIHOT 的数据、特定监控功能或商业条款。

目标是在不改变现有 REST/RSS/Skill 行为的前提下，为支持 MCP 的 Agent 提供结构化、匿名、只读的数据工具。新接口必须默认关闭，并能独立限流和关闭。任何时候都不允许它绕过现有公开内容判定或把运行数据库中的对象直接返回。

对标来源：[AIHOT 更新日志](https://aihot.news/changelog)（重点参考 2026-08-01 MCP、2026-08-02 热点事件页、2026-09-10 事件归组、2026-09-11 逐事件报告）。AIHOT 的公开使用规则属于 AIHOT 自身，本设计不继承或复述其许可政策。

## 备选方案

### A. 维持 REST、RSS、Skill

不新增协议或依赖，风险和维护成本最低。缺点是 MCP-only 客户端不能直接调用工具，且 Agent 接入仍需自行转换 HTTP 响应。

### B. 增加默认关闭的只读 HTTP MCP（推荐）

沿用 AI.BAIZE 已公开的精选、热点、事件、日报/报告数据，为 Agent 增加稳定工具契约。使用官方 MCP SDK 或其官方 Express/Node 适配层；不自造 JSON-RPC/传输实现。优点是直接吸收对标站已验证的 Agent 接入方式；代价是增加协议依赖、远程请求面和维护负担。

### C. 只改进现有 Agent 接入页和 REST 文档

补齐示例与事件查询指南，不提供 MCP。适合推迟协议投入，但不能满足 MCP 客户端原生工具调用。

选择 B。若官方 SDK 无法与当前 CommonJS Express 服务以受支持方式集成，则回退到 A/C 并重新评审，不以未经审查的手写协议实现补位。

## 用户与成功标准

主要用户是连接到 AI.BAIZE 的 Codex、Claude Code、Cursor 等 MCP 客户端。成功标准：

1. MCP 客户端可发现并调用只读工具，获得与网站公开内容一致的结果。
2. 工具输出能保留精选动态、事件聚合及原始来源链接等现有价值，不把 MCP 降格为没有上下文的原始条目列表。
3. `MCP_ENABLED` 缺失或为 false 时端点不可用；关闭后无需改动 REST/RSS/Skill。
4. 自动化测试证明私有/隐藏内容、管理员能力、反馈和其他写操作均不可由 MCP 触达。
5. 默认结果数、时间范围、请求体和响应体均有上限；超限明确报错或裁剪，不无限读取历史数据。

## 架构与工具契约

新增独立的 `/mcp` Streamable HTTP 端点，采用无状态请求，不建立长期会话。MCP 协议生命周期、header 校验、JSON-RPC 与传输编码交给官方 SDK/适配层处理。仅实现客户端发现工具与调用工具所需能力；不提供 MCP Resources、Prompts、订阅、写工具或管理工具。

首批工具：

| 工具 | 输入 | 结果 |
|---|---|---|
| `get_selected_feed` | `take`（默认 20，最大 30）；可选 `since` 游标/时间 | 按当前精选规则排序的公开精选动态 |
| `search_items` | `query`；可选 `mode`（selected/all，默认 selected）、`days`（默认 7，最大 30）、`take`（最大 30） | 公开搜索结果及分页/截断提示 |
| `get_hot_topics` | `take`（默认 10，最大 10） | 当前热点榜及代表来源 |
| `get_event_timeline` | `event_id` | 公开事件摘要、代表报道、时间线与公开关联报道 |
| `get_digest` | `period`（daily/weekly/monthly，默认 daily）、可选 `date` | 指定日期的日报/周报/月报，事件逐条呈现 |

精确字段类型、日期边界和错误码在实施计划中根据实际 builder 定稿。所有工具仅通过现有公开查询与 `serializePublicItem` 等公开投影取数；事件成员逐条应用公开过滤。摘要快照、报告快照必须重新投影到明确字段白名单，不能 `...snapshot` 或返回内部数据库对象。工具结果中保留原文和站内详情 URL，避免复制完整受版权限制的原文。

## 安全、隐私与错误处理

- 开关：新增 `MCP_ENABLED=false` 默认值；关闭时 `/mcp` 返回 404 或服务不可用响应，不影响其他路由。
- 访问：匿名只读，权限不得强于对应公开 REST API。不得暴露 `/api/public/ask`、`/api/admin`、配置、反馈、日志、源健康内部状态或任何写操作。
- 来源校验：遵循所选 MCP SDK 对 Streamable HTTP 的 Origin 与协议头校验。若请求提供 Origin，必须按配置的允许策略验证；禁止无条件接受任意浏览器 Origin。实现前验证 SDK 行为与反向代理部署模型。
- 限流：使用专用 MCP 读取限流器，按 Express `req.ip` 识别客户端（应用当前只信任 loopback 代理）；限额与窗口可配置，MCP 流量不能消耗/绕开现有公开写接口限额。
- 资源边界：校验所有 schema 和枚举；限制日期跨度、返回条数、请求体与序列化输出大小；不接受任意文件路径、URL 抓取或用户提供的查询表达式。
- 错误：对外返回稳定、精简的工具错误（参数无效、未找到、暂不可用、超限）；不返回堆栈、内部路径或数据库字段。记录请求类别、耗时、状态和限流计数，不记录完整用户查询或响应正文。
- 快速关闭：将 `MCP_ENABLED=false` 作为独立熔断开关。生产启用、反代改动和服务重启不属于本设计授权范围。

## 测试与验收

1. MCP 协议集成测试覆盖初始化/能力协商、工具发现、合法调用、无效参数、未找到资源、协议错误和禁用状态；至少使用官方 SDK 客户端或官方推荐测试方式，不只用本地 mock 验证。
2. 每个工具与对应公开 REST 结果做一致性断言，包括公开过滤、精选排序、事件时间线与报告日期。
3. 安全回归测试断言隐藏条目不会从精选、事件成员、日报快照和报告快照的任一路径泄漏；内部字段和未公开正文不出现在序列化结果。
4. 测试 Origin 缺失/允许/拒绝、代理前缀伪造不能轮换限流身份、不同 IP 计数隔离、超限结果及响应大小边界。
5. `npm test`、`npm run typecheck`、`npm run build` 全部通过；现有 REST、RSS、Skill 行为无回归。
6. 在真实 MCP 客户端本地连通验证，并确认默认关闭时不可调用；不部署到生产。

## 明确不做

- 不复制 AIHOT 的 Tibo 额度监控、模型榜或其站点 UI。
- 不调整现有采集、评分、信源策略或日报编辑模型；它们属于不同优化面。
- 不增加付费 API，不新增 MCP 写工具，不做账号/密钥系统。
- 不抓取或镜像 AIHOT 内容，不照搬其使用条款。
- 不改生产 Nginx、生产环境变量、运行数据库或服务状态；后续如要公开启用，须另行评审 Origin 策略、服务限额与使用条款。

## 主要风险与反证条件

1. **能力重复**：若目标 MCP 客户端均可稳定使用 REST/Skill，或没有真实调用需求，则新增接口的维护成本可能超过收益；此时保留 A/C。
2. **暴露面扩大**：默认关闭、窄工具面、只读权限、独立限流和可关闭配置是硬性条件，不能以“匿名只读”替代访问控制审查。
3. **数据泄露**：现有部分日报/历史摘要从状态快照组装，公共 REST 的存在不等于其内部字段均适合 MCP 返回；白名单投影与隐藏数据回归测试不可省略。
4. **SDK 兼容性**：当前服务为 CommonJS + Express。若官方支持的 SDK 版本在该组合中需要不稳定互操作层，停止实现并回到设计选择，不允许自行实现协议规避。
5. **被误认为商业授权**：开放技术端点不等于自动许可第三方再发布数据。BAIZE 的独立使用政策需在生产开放前明确。
