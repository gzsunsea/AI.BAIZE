# 中文摘要不可用：诊断与修复记录

## 已复现的事实

- 生产 API 进程未设置 `OLLAMA_MODEL`，实际使用代码默认值 `qwen2.5:0.5b`，请求超时为 20 秒。
- 对 `item-1ju74bu`（LangChain/CrewAI/OpenRouter 路由分层文章），0.5b 返回英文标题作为 `fact`，被中文校验拒绝。
- 只读测试中，已安装的 `qwen2.5:1.5b` 返回中文事实摘要，但 `reason` 复制了提示词占位语。旧实现因此丢弃了整个结果。一次请求含模型加载用时约 38 秒，超过生产旧超时。
- 旧实现将降级摘录也计入 `enhanced`，记录首个 provider，不能准确表示整批中文摘要成功数。失败后等待 12 小时再试。

依据：本轮读取的生产进程环境、原文 `raw.summary`、Ollama 原始 JSON 响应及 `server/lib/llmEnhancer.js`。上述模型测试未写生产数据库。

## 代码修复

- 摘要与推荐理由独立校验：合格中文摘要保留，不合格或缺失的理由使用中性原文核对说明。
- 文本请求只处理原文，JSON schema 只要求 `fact`，避免编辑理由模板及图片说明抢占摘要任务。
- 已有中文来源摘要直接使用，不因本地模型不可用而改成“中文摘要暂不可用”。
- 降级记录保存模型与失败原因；默认重试间隔调整为 30 分钟，模型更换后不沿用旧冷却期。
- 结果分别记录成功、失败、实际应用数量、各 provider 和各失败原因。采集增强日志不再将部分失败标记为全部成功。
- 待部署配置显式选择已安装的 `qwen2.5:1.5b`，单并发、20 条批次、90 秒超时。最终模型配置须在生产恢复连接后完成新提示词实测和资源核验，不能仅依据结构化测试宣称质量通过。
